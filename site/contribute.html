Contribute hardware

A platform to test, not a single radio to bet on

ARALD isn't being built as a LoRa product with a network protocol bolted on. It's the other way around: the protocol — routing, store-and-forward, priorities, deduplication, identity, sync between intermittent nodes — is deliberately kept separate from whatever carries the bits.

LoRa, Bluetooth Low Energy, and Wi-Fi are all part of the architecture. LoRa is the furthest along today — the first to reach real hardware prototyping — but BLE and Wi-Fi are just as much a part of where this is going, and will be tested against the same protocol.

The current hardware round exists to build a real platform to test that on — not to lock in a final product.

LoRa

Long range, low power

The first transport reaching real prototype hardware. Best fit for sparse nodes far apart — a valley, a coastline, a disaster zone.

Bluetooth Low Energy

Proximity and phones

Short range, but it's already in every smartphone — the natural way a phone becomes a relay without extra hardware.

Wi-Fi

Local bandwidth

Shorter range than LoRa, but far more bandwidth — for larger transfers between nodes that are close together.

The three tiers

Same software, three sizes of hardware

Each tier tests a different question. None of this is the final product — it's the platform we're using to find out what the final product should be.

ARALD Box — the main platform

An always-on computer running content, search, translation, AI and coordination services, paired with a dedicated radio module over USB. Built around the Radxa ROCK 3C (4 GB) — a cheaper alternative to the Orange Pi 4 Pro used as an earlier reference — quad-core ARM Cortex-A55, Gigabit Ethernet, Wi-Fi, Bluetooth, USB 3.0 and NVMe support: enough to run Docker, a database, the web UI and gateway services.

Turns an ordinary x86-64 computer into an ARALD node — no dedicated machine required. The question it tests: can the same node run unchanged across very different host hardware, with only the radio bridge staying constant?

ARALD Card — the node you carry

The smallest ARALD device, meant to be carried directly by a person. Built on the Seeed Studio XIAO ESP32-S3 — dual-core, 8 MB flash, 8 MB PSRAM, and Wi-Fi + BLE already on board — paired with the Wio-SX1262 for LoRa. One board, three possible connectivity modes, no need to build a separate platform per radio.

Why three identical radio kits

One module, three roles

The same XIAO ESP32-S3 + Wio-SX1262 kit is used three times: as the Card's own radio, as the Box's USB bridge, and as the Portable's USB bridge. That lets us test Card ↔ Box, Card ↔ Portable, Box ↔ Portable, and several nodes at once — with one hardware design to build and debug, not three.

Buying these kits isn't a final bet on LoRa alone. It's the first radio link concrete enough to prototype today — BLE and Wi-Fi stay just as much a part of the architecture, and will get their own hardware rounds as they're tested.

What we're testing

Not just "can two devices talk"

The goal is to find out which technology fits which situation — not to decide in advance that one radio should cover every case.

LoRa
  • Range
  • Reliability
  • Power draw
  • Behavior in mountain terrain
  • Talking to intermittent nodes
  • Store-and-forward over radio
Bluetooth Low Energy
  • Card ↔ smartphone links
  • Node discovery
  • Pairing and setup
  • Small message exchange
  • Phones acting as relays
Wi-Fi
  • High-speed local links
  • Nearby-node communication
  • Larger file transfers
  • Acting as a local network when available

The result decides what gets built next — this isn't a checklist to confirm, it's an open question.

Substitutions

Most parts don't need to be exact

None of the components above require a specific brand — an equivalent NVMe drive, USB SSD, Li-Po battery, EU868 antenna, USB-C power supply, case, or cooling solution is fine, as long as it meets the specs.

The one exception, for now, is the XIAO ESP32-S3 + Wio-SX1262 pair — keeping it identical across all three tiers is what makes the cross-testing above possible. Open an issue with the exact model or product link before buying anything not on this list.
