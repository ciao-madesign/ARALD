The mechanism

No towers. No center. No single point of failure.

Even from a car window in the middle of nowhere, a message can still find its way — just not instantly, and not through anyone's server.

How it works

01

Every device is a peer

A phone, a radio card, a fixed relay, a small computer — each one can hold content, pass it along, and ask for more. Nothing routes through a central server.

02

Requests hop until they land

When two devices come within range — Bluetooth, long-range radio, or plain local Wi-Fi — they exchange what they know and move on, carrying requests and answers forward.

03

Nothing has to happen at once

If no one nearby can answer right now, a message waits. The next device that can carry it forward picks it up on the next contact — a hiker, a boat, a relay coming back online.

The hardware

One network, sized to fit the situation

The same software runs on very different hardware, matched to what a situation calls for. None of it needs the internet to talk to each other — a gateway can optionally bridge out when a connection is available, never as a requirement.

ARALD Card

Pocket-sized radio. Sends an SOS, relays other people's messages, or both.

ARALD Relay

Same logic, fixed and solar-powered, or carried along as a courier.

ARALD Box

A small always-on computer: content, local search, translation, AI, coordination.

ARALD Portable

The same environment on a bootable drive — plug into whatever computer is on hand.

Mobile app

A dashboard onto any of the above: browse content, chat, share your location, call a service.

Where things stand

A working prototype, built in the open

Core networking — identity, routing, encryption, store-and-forward, content caching — is implemented and covered by automated tests, running today over real local networks (Wi-Fi/TCP). Radio transports (Bluetooth, LoRa) are implemented behind the same interface the real hardware will use, validated today in software simulation, with a first real LoRa driver already written and tested against a faithful hardware emulator. Application features on top — chat, a community noticeboard, opportunistic location sharing, an emergency SOS beacon, local search and AI services, and deferred delivery of a file to an outside organization once connectivity returns — are built and tested.

We say this plainly because it matters: this is real, working code — not a pitch deck. What's still ahead is hardware, field testing, and scale: the physical devices (Card, Relay) haven't been manufactured yet.
